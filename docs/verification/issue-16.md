# #16 디자인 기반·익명 장터 조회 검증

2026-11-11 로컬 검증. 운영 배포나 GitHub CI 결과를 의미하지 않는다.

## 구현

- 공식 CI 규정 발췌·벡터 로고·자체 호스팅 Pretendard, DESIGN.md·공통 UI·개발용 /design-system.
- 실제 Go 프로세스의 GET /api/v1/products와 GET /api/v1/products/{productId}. 기존 인증·권한·오류·meta와 SQLite를 사용한다.
- /·/market 목록, /products/:id 상세, 검색·앞뒤 페이지·재시도·없는 상품·세션 만료·사진 실패 안내.
- 공개 목록은 승인·비삭제만. 판매자 본인 비공개 상세를 허용하되 일반 장터에서 HR 특권을 추가하지 않는다. 판매자 프로필·메일·전역 사용자 ID를 반환하지 않는다.

## 자동 검사

- Go: go test -race ./..., go vet ./..., go build ./... 통과.
- 프론트: npm ci, 테스트9개(4파일), TypeScript 검사·Vite production build 통과.
- 기존 계약 검증기 Python 테스트2개 통과.
- Impeccable 기계 검사에서 지적 없음. 이는 독립 코드 리뷰가 아니다.

Go 회귀 테스트는 실제 HTTP·세션·SQLite에서 공개 필터·익명 DTO·본인/제삼자/HR 비공개 접근·정지 계정·검색 리터럴/SQL 입력·커서 시각+ID 정렬·0원/1억원·소진/모집 종료·사진 순서와 저장 경로 비노출을 확인한다. 최초 API 및 프론트 조회 테스트의 실패 후 구현했고, 세션 만료 안내도 실패 테스트로 재현한 뒤 수정했다. 나머지 경계 회귀는 구현된 동작에 추가해 확인했다.

## 실제 화면

격리된 .git 내부 SQLite에 가상 상품6개(승인5·대기1)를 넣고 개발 직원 B로 로그인했다. 로그인→목록→사과 검색→상품 상세를 실제 Go 서버와 확인했고, 대기 상품 직접 주소는 찾을 수 없음으로 표시됐다. 이 가상 데이터는 서비스 초기 데이터나 저장소 커밋에 포함하지 않는다.

CSS 기준 viewport 너비360·768·1280에서 2·3·4열, body 가로 넘침 없음. 공식 글꼴 적용 후360px을 재확인했다. 공통 Dialog 열기·Escape 닫기·포커스 복귀도 확인했다. 공식 Ocean Blue/흰색 대비는 약5.19:1이다.

## 리뷰와 남은 연결

공통 kch-review 기준으로 권한·개인정보 DTO·SQL 바인딩·트랜잭션과 단일 연결 사용·늦은 검색 응답 취소·세션 만료를 자체 검토했다. 별도 리뷰어나 독립 리뷰 도구를 사용하지 않았다.

Docker 데몬 소켓이 없어 이번 변경의 Docker 이미지 빌드·컨테이너 검사는 실행하지 못했다. Dockerfile과 Railway 설정은 변경하지 않았으며 실제 Railway 배포도 수행하지 않았다.

#17의 실제 등록→승인→목록/상세 사진 전달, #18의 최종 중복 신청 정책과 canApply 연동은 해당 기능 구현 후 실제 공급자로 확인해야 한다. 현재 사진은 인증된 이미지 API 주소·순서·실패 대체 안내까지 구현했으며 업로드·파일 응답은 #17 범위다. 문의·거래 신청 동작·구글 인증을 완료했다고 표시하지 않는다.
