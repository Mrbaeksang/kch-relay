# 공통 셋업 검증·리뷰 기록

2026-11-05. 대상: 이슈 #4~#9, 실제 Google 인증·업무 기능·운영 배포 제외.

## 실제 검증

- 설정 기본값·오류·production 개발 인증 차단, DB 초기화 실패·정상 종료.
- HTTP 오류·권한·request ID·JSON 형식/크기·panic·제한시간·민감정보 비노출·메타 실패·KST 날짜 경계.
- 기존 사용자 migration 보존, 실제 SQLite rollback·FK·음수 수량 차단·확정 단가 불변·동시 참가자 생성과 순번·중복 거절 알림·미확인 상태 사용자 격리.
- 세션 로그인/조회/교체/회수/만료/정지·계정/역할 위조·CSRF/Origin·원본 토큰 미저장·disabled 경로 차단.
- 프론트 타입 검사·테스트·빌드. API 쿠키/CSRF·401/403 구분·로그인/로그아웃·미확인 표시 초기화·중복 초기 조회 방지.
- 계약 검사기 자체의 잘못된 HTTP 응답·권한 누락·쿠키 보호 누락 탐지.
- 실제 Docker 빌드·정적 파일·개발/disabled 인증·CSRF·권한·로그아웃·재생성 후 DB/파일/세션 보존.
- 실제 브라우저: 관리자 로그인→관리자 API 성공→직원 A 전환→관리자 화면 차단→새로고침 복구→로그아웃.

## 자체 코드 리뷰

독립 리뷰어를 사용하지 않고 팀 kch-review 기준으로 직접 검토했다. 인증 context·역할/소유권 분리, 원본 토큰/개인정보 비노출, 로그인 교체/만료 경계, DB 단일 연결과 tx 내 바깥 DB 재호출 금지, migration 보존, 가드 자동 적용 및 초기화 예외를 확인했다.

리뷰 중 새 업무 모듈이 인증을 빠뜨리지 않도록 인증된 Module 등록 지점을 보완하고 실패 테스트→통과로 검증했다. 요청 크기 제한은 JSON decoder뿐 아니라 글로벌 HTTP에도 적용했다. 확인한 현재 공통 기반 범위에서 남은 차단 문제는 발견하지 않았다. 업무 기능의 정합성은 후속 구현 시 별도 검증해야 한다.

## 한계와 운영 영향

현재 UI는 기능 연결용이며 최종 디자인은 프로젝트 소유자가 담당한다. 실제 회사 도메인·부서/직급·구글 인증·퇴사자 연동은 미구현이다. 사진 업로드 API·상품/거래/쪽지/알림함/통계 화면도 후속 기능이다. 배포하지 않았으며 운영 전 백업·복원과 업무 정책 제한을 확정해야 한다. 개발 인증은 운영에서 사용할 수 없다.


## 로컬 자원 제한

최종 재빌드 중 로컬 디스크 공간 부족으로 Go 병렬 링크와 Docker buildkit 파일시스템 오류가 발생했다. 그 이전 실제 Docker·브라우저 연결 검증은 통과했다. Go 빌드 캐시만 정리하고 병렬도를1로 낮춰 재검증하며, 최종 컨테이너 버전은 GitHub CI의 실제 Docker 빌드·계약 검증 결과를 확인한다. 사용자 데이터·기존 영구 볼륨은 정리 대상이 아니다.
