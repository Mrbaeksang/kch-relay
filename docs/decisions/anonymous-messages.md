# 기능 4 · 상품별 익명 쪽지 결정 기록

작성일: 2026-11-11. 이슈 #19. PRD·API 명세에서 **제안** 또는 미정으로 남은 항목 가운데 구현에 필요한 것을 아래와 같이 정했다. 팀이 다르게 확정하면 이 문서와 코드를 함께 바꾼다. 다른 화면은 아래 값을 하드코딩하지 않고 API 오류 응답(`details.maxLength`)을 사용한다.

## PRD·API 명세 제안을 채택한 항목

| 항목 | 결정 | 근거 |
|---|---|---|
| 새 대화 조건 | 승인(APPROVED)되고 숨기지 않은 상품에서만 새 대화를 연다. 아니면 409 `INVALID_STATE`, 없는 상품은 404. 모집 마감 상품도 문의는 가능하다(문의는 신청이 아니다) | API 명세 5장 제안 |
| 기존 대화 유지 | 이미 있는 대화는 상품의 마감·숨김 뒤에도 조회·발송·읽음 처리할 수 있다 | API 명세 5장 제안, PRD 거래·쪽지 기록 보존 |
| 텍스트만 | 첨부 없이 본문만 보낸다 | API 명세 5장 제안 |
| 신원 공개 유지 | `participants.identity_revealed_at`이 있으면 두 당사자에게 서로의 실명·부서·직급을 보여주고 거래 완료 뒤에도 유지한다. 이메일은 보내지 않는다 | API 명세 4장 제안, #18 결정과 동일 |

## 새로 정한 항목

- **발송 멱등키**: `POST /conversations/{conversationId}/messages`는 `Idempotency-Key` 헤더(1~128자, 공백 없는 ASCII)를 **필수**로 받는다. 키는 `messages.idempotency_key`에 저장하고 (대화, 보낸 사람, 키)에 고유 인덱스를 둔다(migration `00003`). 같은 키·같은 본문의 재요청은 처음 쪽지를 200으로 돌려주고, 같은 키·다른 본문은 409 `IDEMPOTENCY_KEY_REUSED`다. 별도 저장소가 없으므로 키 보관 기간은 쪽지 보관 정책(미정)을 따른다.
- **화면의 키 사용**: 화면은 보내기마다 `crypto.randomUUID()`로 키를 만들고, 실패한 쪽지를 다시 보낼 때는 같은 키를 쓴다. 작성 중인 본문과 키는 그 브라우저의 sessionStorage에 보관해 세션 만료·새로고침 뒤에도 복원하며 전송에 성공하면 지운다.
- **권한 오류**: 대화 당사자(판매자·해당 구매자)가 아닌 사람의 조회·발송·읽음 요청은 404로 응답해 ID만으로 대화 존재를 알 수 없게 한다. 관리자에게 쪽지 열람 권한을 두지 않는다.
- **판매자 목록의 빈 대화**: 구매자가 문의를 열기만 하고 쪽지를 보내지 않은 대화는 판매자 목록에 보이지 않는다. 구매자 목록에는 보인다.
- **읽음 처리 순서**: 쪽지 시각은 대화마다 엄격히 증가하도록 저장한다(같은 밀리초면 직전 쪽지 + 1ms). 읽음 처리는 `throughMessageId`의 (시각, ID) 이하에서 본인이 받은 쪽지만 바꾸므로, 읽음 요청과 동시에 도착한 쪽지는 미확인으로 남는다.
- **목록 미리보기**: 대화 목록의 마지막 쪽지는 앞 100자만 보낸다.

## 입력 상한

| 값 | 상한 |
|---|---|
| 쪽지 본문 | 공백만 있는 본문 거부, 1~2,000자(유니코드 문자 단위). 받은 그대로 저장한다 |
| Idempotency-Key | 1~128자, 0x21~0x7E ASCII |

상수는 `backend/internal/messages/messages.go`, 화면 값은 `frontend/src/messages/model.ts`에 있다.

## 다른 기능과의 연결

- **거래(#18)**: 대화 ID는 거래 응답의 `conversationId`(participants.id)와 같다. 신청하면 같은 대화의 별칭이 ‘문의자 A’에서 ‘익명 1’로 바뀌고, 수락이 `identity_revealed_at`을 채우면 신원이 보인다. 실제 신청·수락 경로로 검증했다(`backend/internal/messages/access_test.go`).
- **장터 조회(#16)**: 상품 화면에 `frontend/src/messages/InquiryButton.tsx`의 `<InquiryButton productId>`를 놓으면 문의를 시작하고 해당 대화로 이동한다.
- **미확인 표시**: 공통 `UnreadMeta`를 그대로 쓴다. 읽음 처리 응답의 meta로 표시가 갱신된다.
